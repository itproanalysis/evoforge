# PR 기준 커밋과 작업 브랜치 보호

`evoforge.github.create_pr`은 변경 파일을 읽기 전에 기준 브랜치의 커밋을 조회하고,
diff와 추가 테스트 파일을 확인한 뒤 브랜치가 같은 커밋인지 다시 확인한다.
기준이 이동했거나 diff/테스트 경로에 문제가 있으면 작업 브랜치를 만들기 전에 거부한다.
이미 존재하는 작업 브랜치에는 파일을 쓰거나 PR을 열지 않는다.

## 서버가 검증한 기준 SHA 사용

호출자가 Runner/서버 증거에 기록된 기준 SHA를 `expected_base_sha`로 전달하면,
브랜치가 그 SHA와 일치해야 하며 모든 원본 파일과 추가 테스트의 충돌 여부를 해당 SHA로 읽는다.
새 작업 브랜치도 정확히 그 SHA에서 만든다. SHA는 소문자 40/64자리 Git 객체 ID여야 한다.
테스트 파일이 기준에 이미 있거나 diff가 같은 경로를 건드리면 기존처럼 거부한다.

기존 호출은 호환성을 위해 파일을 브랜치 ref로 읽고 읽기 전후의 브랜치 SHA를 비교한다.
그 사이 ref가 이동했다 원래 값으로 돌아오는 경우까지 고정할 수는 없다.
정본 공개 경로는 서버의 검증된 기준 SHA를 명시적으로 전달해야 하며 이 연결은 아직 완료되지 않았다.

새 브랜치를 만든 뒤 파일 쓰기에 실패하면 부분 브랜치가 남을 수 있다. 다른 요청의 브랜치로 간주해 덮어쓰지 않는다.
실제 병합 전에는 현재 기준과 검증된 후보 head를 다시 확인하고 정본 `core.authorize_merge`를 거쳐야 한다.

## 검증 범위

새 회귀 테스트는 실제 로컬 Git 커밋 두 개와 합성 GitHub HTTP transport를 사용한다.
기준 이동·이동 후 원복, 고정 SHA 파일/추가 테스트 조회, 기존 작업 브랜치 거부와 입력 오류를 확인한다.
기존 승격 Critic 테스트의 ref 기반 호출과 테스트 충돌 거부도 유지한다.
이 검증은 실제 GitHub PR 생성이나 운영 배포가 아니다. Muse Spark 기본값은 유지한다.
