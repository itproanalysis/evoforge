# EvoForge v3.5 — 기술 결정 및 변경 검토

## ADR-035: Context Mesh 도입
채택: API 중립 컨텍스트 패킷 + 서버 상주 암호화 원문 보존 + 역할별 선별 전달 + 공급사별 캐시. 거절: 서로 다른 모델 간 KV Cache 공유, Chat 세션 자동 지속 실행 가정.

## ADR-036: Caveman 오픈소스 도입 방식
현재 main `LICENSING.md`에 따르면 3.0.0 이상 Apache-2.0. 직접 도입은 P1 기술검증. 초기 P0는 Caveman의 복원 가능한 구조만 재현하고 거대한 Go Proxy를 Provider Broker 필수 의존성으로 만들지 않는다. 채택 시 태그/커밋 고정·NOTICE·테스트·SBOM·네트워크 차단·처리량 부하평가 수행.

## ADR-037: 복원은 인증과 분리
ref는 랜덤 식별자이며 ACL/RLS로 보호한다. 원문 저장/복원 실패는 요약으로 리뷰 승인하지 않고 안전하게 중단한다.

## ADR-038: 압축은 비용·캐시·품질 동시 최적화
단순 o200k_base 토큰 추정과 실제 공급사 청구량은 다르다. 압축은 캐시 Prefix 적중률을 떨어뜨릴 수 있어 품질 게이트 통과 후 Net Benefit으로 비교. 개별 모델의 지원 기능·가격 및 데이터 정책을 독립 Registry로 관리한다.

## ADR-039: 품질 보호 우선
Critic은 전체 변경 Diff와 실패 테스트의 원문을 검증한다. 최종 승인·테스트 파이프라인·보안 정책의 원문은 압축 대체 금지. 새로운 압축기 자동 승격 불허.

## ADR-040: 5-Agent×10X의 공정 실험
단일 모델, 단순 5병렬, v3.4 어댑티브 5, v3.5 컨텍스트 최적화 5를 동일 작업/예산/품질 조건으로 비교한다. 10배는 목표이며 결과값을 측정 전 주장하지 않는다.
