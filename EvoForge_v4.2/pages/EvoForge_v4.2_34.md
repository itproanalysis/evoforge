# 34. 격리 실행기(Cloud Sandbox)

> **목적:** 신뢰할 수 없는 고객 코드를 실행해도 다른 고객·플랫폼·키가 노출되지 않게 한다. · **결정:** D-037, D-019, D-047, D-050, D-055 · **계약:** —

### 구조
Control Plane과 Execution Plane을 네트워크·권한·컴퓨트 풀로 분리한다. 신뢰할 수 없는 코드는 **microVM급 강한 격리**(Firecracker 계열 등)에서 실행하는 것을 기본으로 한다. 일반 컨테이너만으로 멀티테넌트 격리를 주장하지 않는다. 후보 공급자(E2B, Daytona 등)는 격리 강도·egress 기본값·데이터 보존·cold start·지역·가격을 M0에서 실측 비교한다.

### 기본 정책
비루트 사용자, 읽기 전용 베이스 이미지, 필요한 임시 경로만 쓰기, seccomp/capability 제한, 호스트 Docker socket 미마운트, **outbound deny by default**(패키지는 allowlist 프록시·캐시), CPU·메모리·시간 상한, 실행마다 고유 자격 증명과 TTL. **공급사 키·KMS·클라우드 메타데이터에 접근 불가**(플랫폼 키에서는 특히 중요). 테스트 로그·산출물은 전송 전에 비밀 탐지·마스킹한다. egress 확대는 별도 승인.

### 풀 분리
개발 Runner와 검증 Runner는 슬롯을 공유하지 않는다. 검증 Runner는 후보 에이전트가 쓸 수 없는 테스트 데이터·평가기·서명 키를 쓴다. CI 결과는 깨끗한 새 Sandbox에서 재평가한다(pristine regrade). 연구 코드(M6)는 네트워크 차단 정적 분석 → 라이선스·의존성 승인 → 별도 에페메럴 Runner 순서로만 실행하고, 고객 비밀을 마운트하지 않는다. 조직별 공정 스케줄링과 egress 한도를 둔다. 서명·검증된 사전 빌드 이미지로 cold start를 줄이되 고객 코드·비밀을 이미지에 캐시하지 않는다.

### 읽기 전용 투기 실행(D-047, TRIAL)
도구 대기를 숨기려고 다음 호출을 미리 실행할 수 있다. 단, **읽기 전용 5종**(`fs.read`, `fs.list`, `search.code`, `git.read`, `ctx.retrieve_evidence`)만 투기하고, 공급사 호출(과금)·GitHub·과금·배포·쓰기·셸·네트워크는 투기하지 않는다. 투기 결과는 copy-on-write 스냅샷에서 만들고, 원래 순서대로 커밋하며, 투기 이후 앞선 호출의 write set과 자기 read set이 겹치면 버리고 다시 실행한다. 동시 투기 최대 4개. 불변식은 "순차 실행과 결과가 항상 같다"(거짓 수락 0). 근거: 2609.38201(1.27–1.35배, 커밋 검증 4,010건 거짓 수락 0). read set은 Tool Runtime이 추적하며 선언에 의존하지 않는다.

### 평가 샌드박스 위생(D-050)
봉인 평가·벤치마크 Runner는 기존 clone을 제자리에서 정리하지 않는다. **base에서 도달 가능한 객체만 받는 새 저장소를 만든다**(`reference_impl/eval_hygiene.py`, D-055): 임시 bare clone에서 base에 브랜치를 걸고 `--no-local --single-branch --no-tags`로 clone → remote 제거 → reflog 만료 → hooks 비움. 실행 전 감사 7항목(remote 없음, ref 1개, HEAD = base, alternates 없음, reflog 비어 있음, 알려진 미래 커밋 없음, 모든 커밋이 base의 조상)을 통과해야 한다. 같은 저장소를 그냥 clone 후 checkout하면 미래 커밋과 remote가 남는다는 것을 대조 시험으로 확인했다. 점수 행은 `score_record()`로만 만들고, scaffold 5필드(name, version, turn_cap, model, harness_version)가 없거나 감사 위반이 있으면 기록을 거부한다(공개 벤치마크에서 미래 이력 악용이 보고됨).

### 정리와 악용 방지
종료 시 디스크·볼륨 삭제, 강제 중단 시 프로세스 트리 종료, 좀비 Run·비용 누수 감시. 채굴·스캔 등 비정상 패턴(CPU 포화 지속, 차단된 egress 시도 급증)을 탐지해 Run을 멈추고 조직을 검토 대기로 둔다.
